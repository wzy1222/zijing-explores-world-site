个人创业与公开挑战主文档 ​

本文件是用户个人创业目标、认知演化、个人 IP、公开内容、粉丝交流和跨项目成长的唯一长期沉淀入口。具体公司的经营细节留在各自项目中；这里记录个人主线、方法与项目接口。

1. 当前状态 ​

  • 长期目标：通过持续创业赚到第 N 个 100 万元，并让能力、知识、信用和关系在不同阶段复利。
  • 当前阶段：长期挑战总纲与第一季项目选择阶段；具体项目选定后第一季才正式开始。精确收入统计口径和起始时间仍待冻结。
  • 多季结构：每一季选择一个具体项目，目标是通过该项目挑战一个新的 100 万；一季允许达成、失败、停止或转型，只有符合冻结口径的真实个人所得达标，100 万计数才增加。
  • 当前收益焦点：每一季的直接收入必须来自当季真实项目创造的客户价值；粉丝、信用和关系不是当季收入的替代证据，但持续价值形成的自愿信任可能跨季复利，为下一季带来更多信息、反馈、验证机会和传播基础。
  • 创业项目：当前尚未确定。项目寻找、筛选、试错和最终选择本身就是挑战的一部分，不预设海鲜或其他具体方向。
  • 更新节奏：每周发布一次，不固定星期几；无论成功、失败、停滞还是改变方向，都持续更新。
  • 内容主线：记录创业的真实过程、点滴行动、结果、情感、判断、问题和修正，并把当周思考提炼为体系化认识，而不是成功后重新包装故事或只做流水账。
  • 底层原则：真诚、坦诚、可验证。允许表达赚钱欲望、焦虑、失败和分歧，但不虚构情绪、成绩或他人贡献。
  • 个人 IP：通过长期一致的真实行动、公开记录、知识沉淀和责任承担逐步形成，不先设计夸张人设。
  • 知识库：创业目标、项目选择、执行、事实、失败、反馈、修正和结果的全过程都进入知识库，同时形成持续更新的全局认知和不可静默改写的每周快照。所有知识都有完整文字版本。本地 Markdown 与 Git 是唯一真相源；短期用 VitePress 生成 Webpage，作为对外阅读层，不建设飞书镜像和站内评论系统。
  • 主公开网站：https://wzy1222.github.io/zijing-explores-world-site/，直接由本仓库内容构建；当前已公开，任何人获得链接后均可直接访问。
  • 备用站点：https://zijing-explores-world.wuzhenyu-wzy.chatgpt.site 已公开，但 2026-07-26 从香港网络出口实测被 Cloudflare 返回 403，不再作为对外主地址。
  • 粉丝与社群：公开内容可能形成关注；愿意持续交流的人可以自愿进入社群。社群首先用于问题发现、交流与共同学习，未来变现必须建立在真实价值交换上。

个人 IP 品牌 ​

  • 个人母 IP：子敬探索世界；
  • 创业栏目：子敬创业；
  • 栏目口号：从零单排；
  • 长期母挑战：创业赚到第 N 个 100 万。

“从零”指从项目尚未确定、没有结果和未经包装的真实起点开始公开记录。“单排”指以用户个人第一视角形成判断、推进个人职责内的行动并承担结果，不等于一个人包办创业，也不排斥朋友、合作伙伴、公司和团队。发生合作时，必须继续区分个人判断、个人贡献、他人贡献和共同成果。

总纲中的底层思路是：坦诚清晰、知行合一、开放独立、创造价值。它们不是另一套流程，而是托住目标、多季结构、单季循环和跨季复利的抽象地基。“坦诚清晰”指说真话，并把事实、判断和边界表达清楚；“创造价值”首先指让当季项目持续创造真实价值；当前不再单独设置“核心信念”模块。

2. 一句话框架 ​

通过一季又一季的真实创业赚到第 N 个 100 万元；每一季围绕一个具体项目，每周如实同步行动、结果、思考与修正，并把能力、知识、信用和自愿关系持续带入下一季。

五个底层支点 ​

  1. 坦诚：不编造、不夸大、不选择性报喜，清楚区分事实、判断、未知、他人贡献与保密边界；
  2. 认知：把事实和经验提炼成能够指导选择、解释因果并说明边界的结构；
  3. 执行：让判断进入现实行动，用结果检验认知；
  4. 共创与修正：接收粉丝和外部世界的问题与建议，由用户核验、行动、公布结果并承担责任；
  5. 互利价值：关系和收益必须建立在真实帮助、自愿选择、透明边界与可退出的价值交换之上。

详细解释持续更新在 创业挑战的底层逻辑。

3. 三个相互连接的引擎 ​

3.1 真实创业引擎 ​

text
发现并验证真实问题
→ 筛选并选择创业项目
→ 投入时间、资金、能力和责任
→ 采取行动
→ 获得经营结果
→ 形成真实税后所得
→ 推进第一个或下一个 100 万元

这个引擎决定挑战是否真实。播放量、点赞和群人数不能替代经营结果。

总纲图同时表达三层：多季挑战结构、每一季共用的单项目周循环、跨季持续累积的能力知识与信任关系。公开记录和知识沉淀贯穿每一季；粉丝与关系复利为下一季提供可能更好的起点，但不进入当季 100 万的直接收入统计，也不保证下一季成功。

需要区分季入口和每周循环：选定一个具体项目是每一季开始前的一次性入口，不属于每周重复动作；项目选定后，公开内容和 Top 5 共创都必须围绕当季同一个项目中的真实行动、结果和问题展开。

单个项目内的每周行动闭环是：

text
推进本周具体行动
→ 记录事实、结果与问题
→ 形成自己的思考和当前判断
→ 每周公开真实进展
→ 真诚听取粉丝建议
→ 选择最多 5 个真实代表问题
→ 自己思考、核验并回答
→ 决定坚持、修正，还是暂不判断
→ 调整下一周行动
→ 继续推进同一个项目

真实经营结果和符合冻结口径的个人所得在循环之外持续累计，用于衡量当季是否达成一个新的 100 万。

3.2 内容与知识引擎 ​

text
完整记录创业落地过程
→ 区分事实、情感、他人输入和个人判断
→ 复盘哪里对、哪里错
→ 修正认知与适用边界
→ 形成体系化认识或待验证假设
→ 画成一张认知图片
→ 用简短视频说明
→ 每周公开一次进展
→ 全过程与产出写入知识库

视频是简要表达，图片是认知压缩，知识库承载完整过程和持续演化的体系。第一阶段先把三者稳定跑通，不追求复杂制作。

3.3 每周公开与反馈引擎 ​

text
每周公开一次真实进展
→ 成功、失败、停滞都同步
→ 获得评论、质疑、建议和共鸣
→ 选择最多 5 个真实代表问题
→ 给出当前回答
→ 能行动的进入下一轮创业实践
→ 公布后续结果和修正
→ 问题、回答、行动与结果写回知识库
→ 愿意持续交流的人自愿进入社群

这个引擎的核心不是“经营粉丝”，而是让外部问题真实进入思考与行动。没有足够问题时不凑满 5 个。

这里的 Top 5 是行动机制，不只是内容栏目：用户真诚收集粉丝评论中的问题、建议与反驳，选出最多 5 条真实且有代表性的评论，亲自思考、核验、回答并总结，由此更新当前认知；其中能够行动验证的部分进入下一轮项目实践，再公开结果并写回知识库。粉丝提供外部输入，最终判断与责任仍由用户承担。

4. 长期复利逻辑 ​

第一个 100 万元可能更难，原因可能包括：

  • 尚未形成稳定的赚钱能力；
  • 没有被验证的产品、渠道和流程；
  • 个人信用与受众关系从零开始；
  • 还不知道什么值得做、什么不值得做；
  • 许多工具、模板和判断无法复用。

后续 100 万元可能更容易，前提是上一阶段真正留下了：

  • 可迁移的创业能力；
  • 被现实验证的认知；
  • 可复用工具与流程；
  • 长期可信的个人 IP；
  • 自愿且持续受益的社群关系；
  • 可持续产品、服务、渠道和资本。

因此：

“第一个 100 万元最难，后面会更容易”是复利假设，不是必然规律。

跨季复利分为两类：

  • 能力与知识复利：认知、执行、工具、流程和知识库在项目之间迁移；
  • 信任与关系复利：每一季持续提供真实价值，愿意留下的人形成自愿关注、互信、高质量反馈和潜在共创关系。

粉丝数量本身不会自动复利。真正可能复利的是持续价值形成的自愿信任，它可能降低下一季的信息获取、需求验证和传播成本，但不能替代下一季的真实项目、交付和责任。

如果每个项目都从零开始、没有沉淀能力和信用，后续不会自然变简单；规模扩大还可能带来更高复杂度和风险。

5. 个人 IP 的定义 ​

个人 IP 不是一个固定人设，而是别人对以下事实形成的稳定预期：

  • 这个人会真实记录，不只展示成功；
  • 会把认知变成行动；
  • 会公布事实、结果和判断变化；
  • 会认真回答问题，也允许别人纠错；
  • 不知道时承认不知道；
  • 能把复杂过程画成普通人可以理解的结构；
  • 会长期积累，而不是追完一个热点就消失。

个人 IP 的核心证据链是：

text
公开承诺
→ 真实行动
→ 可检查结果
→ 诚实复盘
→ 认知修正
→ 下一次兑现

6. 公开内容架构 ​

固定节奏 ​

  • 每周发布一期进展，不固定星期几；
  • 统计周期原则上覆盖本周，具体截止时间在第一期前冻结；
  • 没有收入或明显成果也照常发布，真实说明做了什么、为何没有结果以及下一步如何调整；
  • 当周没有行动时，必须如实说明，不用空泛观点掩盖停滞；
  • 第一阶段的主要形式是一张认知图片加一条简短视频，知识库保存完整版本。

每周一期的最小结构 ​

每条主要内容优先回答：

  1. 我正在挑战或解决什么；
  2. 为什么现在做；
  3. 我采取了什么行动；
  4. 发生了什么事实与结果；
  5. 我当时有什么真实情感；
  6. 原来的判断哪里对、哪里错；
  7. 现在形成了什么认知架构；
  8. 这个判断的边界是什么；
  9. 下一步准备验证什么；
  10. 观众可以提出什么具体问题或反驳。

内容不要求每次都包含十项，但每期至少要有：真实进展、事实结果、思考过程、体系化认识、下周验证。不能只剩观点、鸡汤、营销话术或未经整理的流水账。

每周内容的三层产物 ​

  1. 日期正文 / 每周快照：保存行动、材料、证据、思考过程、失败、未知与修正，能够脱离图片和视频独立阅读；正文审核冻结后即成为当周快照，不再复制第二份同内容文件；
  2. 一张认知图片：把本周最重要的判断链、因果关系或认知框架画清楚；
  3. 一条简短视频：用个人口述解释图片，补充真实情感、现场细节和下一步行动。

7. 知识库结构 ​

知识库不是发布内容的归档箱，而是个人创业过程的完整认知底座。它同时使用两种组织形式，两者缺一不可。

7.1 全局认知：维护“现在怎么看” ​

  • 保存当前对创业全局最完整的理解，包括总体框架、关键判断、因果关系和适用边界；
  • 当认知发生变化时，直接更新原来的主题文字和原来的全局图，不重复制造多个互相冲突的“最终版”；
  • 每次更新要说明新增、修正或否定了什么，并链接触发变化的每周快照；
  • 全局认知回答的是：基于截至今天的全部实践，我现在怎样理解创业？

7.2 每周快照：保存“当时怎么想” ​

  • 每周固定形成一份带日期的文字快照，保存当周行动、事实、结果、情感、问题、推理和当时结论；
  • 快照发布后不静默改写原判断。以后发现错误时，通过补充说明或后续快照修正；
  • 连续快照应该能够还原项目选择、行动、失败、转向和认知演化的完整过程；
  • 每份快照都链接本周影响到的全局认知主题；
  • 每周快照回答的是：在当时的信息条件下，我看到了什么，又为什么这样判断？

7.3 全部知识都有文字版本 ​

  • 全局图必须有对应文字解释；
  • 每周图片必须有对应的完整周快照；
  • 视频必须有脚本、提纲或等价文字稿；
  • 评论问答与后续修正也必须写成文字；
  • 图片、视频和音频负责降低理解成本，文字负责保存完整信息、检索、组织和学习。

7.4 内容主题 ​

在上述两种组织形式下，知识至少包含五类主题：

  1. 第 N 个 100 万元进度：口径、行动、投入、真实所得和差额；
  2. 创业项目记录：项目缘起、角色、判断、行动、结果和退出；
  3. 认知架构：从真实事件中形成的图、判断链、边界与后续修订；
  4. Top 5 问答：原问题、回答、证据、行动、后续结果和修正；
  5. 决策与失败：为什么做、为什么不做、损失什么、后来怎么看。

每周记录完成后，还必须把新认识连接到已有主题：它支持、修正还是推翻了什么旧判断。于是全局认知提供当前地图，每周快照保留历史路径，两者共同构成完整的思考过程。

本地、Webpage 与反馈渠道 ​

  • 本地 personal_thinking 的 Markdown 与 Git 历史保存完整、可追溯、可持续修改的唯一真相源；
  • VitePress 只把同一批 Markdown 生成方便阅读和搜索的公开 Webpage，不复制维护第二份正文；
  • Webpage 首先服务第一次进入的读者，首页优先展示“现在怎么看”和推荐阅读路径；每周快照用于还原判断如何变化；
  • 短期不建设飞书镜像，也不在网站内建设评论系统。反馈继续来自抖音、小红书等实际发布平台的评论区，由用户筛选后写回本地；
  • 外部读者可以提出建议，但不能直接修改全局认知或每周快照；
  • 公开页面不包含账号凭据、客户隐私、合作方保密信息和未经允许的评论、群聊原话；
  • 只有当段落级讨论或稳定协作成为真实需求时，才重新评估飞书或网站评论层。

8. Top 5 问答闭环 ​

与每周进展同步运行；问题不足时少于 5 个，不制造形式主义。

text
收集公开评论与社群问题
→ 合并重复问题
→ 选择最多 5 个代表问题
→ 标注事实、判断与未知
→ 给出当前回答
→ 能行动的转成现实任务
→ 下一期公布结果
→ 更新知识库原答案

优先选择：

  • 多人反复提出的问题；
  • 能暴露当前认知漏洞的问题；
  • 回答后能够推动真实行动的问题；
  • 与当前创业挑战直接相关的问题；
  • 有代表性但不泄露隐私的问题。

不优先选择：

  • 只为了制造争议的问题；
  • 无法核验却要求确定结论的问题；
  • 涉及他人隐私或保密经营信息的问题；
  • 与当前主线无关、只为追热点的问题。

9. 粉丝、社群与合理变现 ​

关系顺序 ​

text
公开价值
→ 自愿关注
→ 持续交流
→ 建立信任
→ 发现真实需求
→ 提供匹配的产品、服务或项目
→ 自愿购买与真实交付

粉丝不是个人拥有的资产，联系方式也不等于信任。真正可以长期积累的是：

  • 观众对用户判断方式的理解；
  • 用户持续兑现公开承诺形成的信用；
  • 社群成员持续获得的实际价值；
  • 双方自愿、透明且可退出的关系。

未来可能的变现来源 ​

  • 用户参与或创办的真实商业项目；
  • 已被验证的工具、产品或服务；
  • 基于真实能力的咨询、陪跑或知识服务；
  • 与个人价值观和受众需求一致的合作。

这些只是可能方向，不代表当前已经成立。变现前必须说明：为谁解决什么问题、交付什么、价格多少、风险是什么、收入归个人还是具体项目。

10. 从朋友公司获得灵感的边界 ​

  • 可以公开自己的观察、学习过程和由此产生的新判断；
  • 朋友的经营经验、内部数据和独有方法必须标注来源并遵守约定；
  • 不把朋友的公司案例包装成个人独立创造；
  • 不公开客户隐私、供应商条款、经营敏感数据和未获授权的内部讨论；
  • 真正属于个人的新认知，应说明它如何从多个事实、行动和反馈中形成。

11. 与具体创业项目的接口 ​

  • 当前挑战尚未确定具体创业项目；项目选择与验证过程可以先成为公开内容；
  • 一旦项目确定，要单独冻结用户角色、合作关系、收入归属、可公开内容和退出边界；
  • 具体项目负责真实产品、服务、交易和履约；本项目负责个人行动、公开表达、知识沉淀和跨项目认知；
  • 任何既有合作项目都不会自动成为第一个 100 万元挑战的主项目，必须经过明确选择。

12. 需要继续冻结的问题 ​

  • 第一个 100 万元具体统计哪些真实税后所得，起始日期是什么？
  • 第一个进入验证的创业问题和项目是什么？用什么标准选择？
  • 第一季选择哪个具体项目？使用什么标准决定开始、停止或转型？
  • 已暂缓：短期不建设飞书镜像；待出现真实的段落级讨论或稳定协作需求后再评估；
  • 社群在出现多少持续互动者、哪些真实需求后才值得建立？
  • 每周一期的统计截止时间、发布时间和最小合格内容是什么？
  • 哪些内容可以公开，哪些必须保密或延迟公开？
  • 未来每一种变现方式分别归个人还是归具体公司？

13. 下一步 ​

  1. 冻结第一个 100 万元的统计口径、起点和个人公开账本；
  2. 建立第一期周记录，真实说明“项目尚未确定”以及当前选择标准；
  3. 从第一期记录中提炼一张认知图片；
  4. 每周用图片加简短视频同步一次进展，无论成功或失败；
  5. 将完整行动、证据、思考、问答和修正写入本地知识结构，并连接到已有认知主题；
  6. 用 VitePress 把同一批 Markdown 生成为公开 Webpage，先手工跑通并核对阅读路径；
  7. 连续 2—3 期后，根据真实维护摩擦决定是否增加自动构建和发布工具。

14. 每周知识生产与发布工作流 ​

完整操作规范见 weekly-knowledge-publishing-workflow.md。当前确认的主链路是：

text
对话、笔记、事实、材料与思考
→ 沉淀带日期的正文草稿
→ 提炼认知变化并更新全局认知原文与原图
→ 审核正文并冻结为当周知识快照
→ 从同一正文派生总结图片和视频
→ 生成并人工检查视频
→ 由 VitePress 从本地 Markdown 生成公开 Webpage
→ 检查首页、当前认知、每周快照、媒体和链接是否正确
→ 发布内容平台，收集评论并把有效反馈写回下一周

“先更新全局认知，再冻结日期正文为快照”是最终整理顺序，但不能丢掉更新前的周草稿、证据和旧判断。日期正文既是面向本周的完整文字，也是历史快照；图片和视频只是它的派生表达。

第一期使用现有 OpenMontage 中的 HyperFrames 路线制作信息图驱动的竖屏短视频。当前本机项目中未发现名为 HyperCam 的视频合成路线；如果用户说的 HyperCam 实际指 HyperFrames，则该路线适合一图、多段文字、高亮和简单转场。第一期不建设复杂自动化，先人工跑通完整链路。
